Slide 2 • Architecture & Choices

Interface Choices, Key Functionality & Deliberately Rejected Decisions

Key Implemented Capabilities

  • ✓ Composite Identity: Keyed strictly on (source_type, source_id) with unique MongoDB compound index.
  • ✓ Revision Preservation: Update batch modifies existing record in-place; manual overrides survive all re-imports.
  • ✓ Evidence Viewer: 1-based numbered turns with timecodes for meetings and exact quotes for calls.
  • ✓ Real Output Exports: Generates real physical report files, JSON/CSV manifests, and downloadable ZIP.
One Deliberately Rejected Decision

Fabricating Pipeline Values & Account Joins

Considered Alternative: Building flashy pipeline forecast gauges and automatically merging companies with similar names (e.g. Harborpath Advisory M01 and Harborlight Advisory C01).

Why Rejected: The assignment rules explicitly state there is NO CRM opportunity table, and similar names are NOT confirmed account identities.

Accepted Trade-off: Prioritized authentic, source-backed metrics (Usable Coverage 18/44) over misleading speculative forecasts.

Trade-offs, AI Usage, Known Limitations & Next Improvements

Engineering Trade-offs & AI Usage

  • • Pregenerated Grounded Analysis: Chose verified, turn-referenced analytical templates over live paid LLM calls to prevent runtime hallucinations and guarantee reproducible test runs.
